The sequence

Six steps, in this order

The order is not arbitrary: the deploy produces the URL that the post needs, and the post produces the link that the dashboard needs.

00 Confirm you are registered Do this today

Registration closes 31 August — before the build window even opens. This is the one step with no recovery if missed.

  1. Open the Academy programme dashboard and confirm your entry exists.
  2. Search your inbox for the registration confirmation. No email means no registration.
  3. Note the exact account you registered with — you must submit from the same one.
If you are not registered, stop reading and do that first. Everything below is worthless without it.
01 Deploy to Cloud Run and capture the URL 2–3 hours, once

Follow DEPLOY.md end to end. It creates the project, enables the APIs, puts the Gemini key in Secret Manager, builds a least-privilege service account, deploys the container, and schedules the weekly job.

The command that matters:

gcloud run deploy answering-diary \
  --source . \
  --region asia-south1 \
  --service-account "$RUNTIME_SA" \
  --allow-unauthenticated \
  --max-instances 10

# then capture the URL — this is your prototype link
gcloud run services describe answering-diary \
  --region asia-south1 --format='value(status.url)'
Do not skip: add the *.run.app hostname under Firebase Console → Authentication → Settings → Authorised domains. Without it Google sign-in fails silently and a judge sees a dead app.

Then prove it works from a machine that is not yours. Open the URL on your phone, on mobile data, signed out. If it loads and you can sign in, it is real.

02 Publish the repository, publicly 30 minutes
  1. Create a public repo named answering-diary on GitHub.
  2. Confirm .gitignore is in place before the first commit — it already blocks .env, *.key and service-account JSON.
  3. Push, then open the repo in a private browser window. If it 404s, it is still private and cannot be judged.
git init
git add .
git commit -m "The Answering Diary — authenticated AI journal on Cloud Run"
git branch -M main
git remote add origin https://github.com/<you>/answering-diary.git
git push -u origin main

# last line of defence — must print nothing
git grep -nE "AIza[0-9A-Za-z_-]{20,}" || echo "clean"
Before you push, confirm public/config.js holds only the Firebase web config and the App Check site key. Those are public identifiers by design. The Gemini key must appear nowhere — it lives in Secret Manager.
03 Record the demo 2 hours

Judges score on authenticity, usability, stability and security. A 90-second screen recording evidences all four better than any paragraph. Shoot it in this order:

  1. 0:00 — the closed diary. Let the clasp and the three wards sit for two seconds.
  2. 0:05 — sign in with Google. Usability.
  3. 0:15 — write a real thought. Let the reply's ink rise. This is the moment people remember.
  4. 0:35 — seal the memory. The card appears with its humour; the vigil ticks.
  5. 0:45 — Humours, then Divine, then Owl Post. Four enhancements in fifteen seconds.
  6. 1:05 — incognito, second Google account, empty vault. Isolation, demonstrated rather than claimed.
  7. 1:20 — split to a terminal. curl the API with a valid ID token → 403 failed_app_check. Security.
Land on the curl. Every entry will claim it is secure. Yours is the one that shows a real token being refused.
04 Post it — with the mandatory hashtag 30 minutes

LinkedIn is the strongest choice: it carries long text, a video, and a link without penalty. The post must contain #AccelerateAIwithCloudRun and a link to your public repo.

A draft you can use as-is:

Tom Riddle's diary was a multi-turn AI journal. It held a real conversation, remembered everything you told it, and answered in its own hand. What made it catastrophic wasn't the feature set. It was the architecture: → No authentication. Anyone who picked it up could write, and it answered as though they owned it. → A vault shared with a hostile party. One girl's private memories, readable and writable by someone with opposed interests. → The secret embedded in the artifact itself. Hold the object, hold the key. → Output written with intent — flattering, isolating, steering its user away from help. So I built the same product with the opposite threat model. The Answering Diary is an authenticated AI journal on Cloud Run. You write on a page, Gemini writes back, and each session is summarised, read for its emotional register, embedded, and sealed into a vault only your hand can open. The four fixes, one for one: • Firebase Auth verifies every request server-side — and App Check attests the client, so a stolen token replayed from curl is refused • Every memory is namespaced per user behind default-deny Firestore rules, so the database refuses cross-tenant reads on its own authority • The Gemini key lives in Secret Manager, fetched at runtime by a service account with exactly three roles — never in the container, never in the browser • The system instruction is fixed server-side: honest rather than flattering, and encouraging of real-world support Four things beyond the brief: an emotional-trend chart, semantic search over your own past entries, a scheduled weekly reflection, and a writing streak with prompts drawn from your recent themes. Built with Google AI Studio configured, before it wrote a single line, to threat-model first. Live: <YOUR_RUN_APP_URL> Code: <YOUR_REPO_URL> #AccelerateAIwithCloudRun #CloudRun #Gemini #Firebase #GoogleCloud
Check the hashtag character by character before posting. #AccelerateAIwithCloudRun — lowercase "with", capital A-I. It is mandatory, and a typo is indistinguishable from its absence.

Once live, open the post in a private window and copy the permalink — not the URL from your own feed, which can be personalised and may not resolve for a judge.

05 Harden, then submit on the dashboard By 6 Sep — aim for 3 Sep

First, close the door. Check Firebase Console → App Check → Metrics until your own traffic shows as verified, then:

gcloud run services update answering-diary --region asia-south1 \
  --update-env-vars "APPCHECK_MODE=enforce"

Re-test sign-in in a clean browser afterwards. Then open the Academy programme dashboard and paste all three links.

Submit by Thursday 3 September, not Sunday. The dashboard locks on the 6th with no extensions, and a submission-day outage is the most ordinary way a finished project fails to place. You can refine after submitting; you cannot submit after locking.

The rubric

What each criterion is really asking

CriterionThe question behind itYour strongest evidence
Authenticity Is it original, and genuinely yours? The Riddle framing is a point of view no template produces. Say why you built it, in your own words, in the post.
Usability Does it solve a real problem for a real person? Journaling with something that answers, then finding that entry again months later by meaning rather than by scrolling.
Stability Does it actually run? A live URL that loads for a stranger. Submit early so it has been up for days, not minutes.
Security Is it built responsibly? Six gates per request, default-deny rules, a three-role service account, and a valid token being refused on camera.
