An authenticated web app where you write on a page and the page writes back — every session summarized, read for its humour, embedded, and sealed into a vault only your hand can open.

The premise

Tom Riddle built this app first. His threat model was the problem.

A diary that holds a multi-turn conversation, remembers everything you tell it, and answers in its own hand — that is a product spec, and it is very nearly ours. What made his catastrophic was not the feature set. It was four decisions any engineer would recognise.

His diary Anyone who picked it up could write in it, and it answered as though they were its owner. There was no notion of whose hand was on the page.
This one Identity is proven on every request, and the client itself is attested — a valid token replayed from elsewhere is still refused. verifyIdToken() + App Check → 401 / 403
His diary One girl's private memories sat in a store a hostile party could read and write at will. A single vault, shared by two principals with opposed interests.
This one Every memory is namespaced to its writer, and the database refuses cross-tenant reads on its own authority — not the application's. users/{uid}/memories · default-deny rules
His diary The secret that animated it was embedded in the object itself. Destroy the artifact, destroy the key. Hold the artifact, hold the key.
This one The key lives outside the artifact entirely, is fetched at runtime by an identity that is allowed to ask, and rotates without a redeploy. Secret Manager · versions/latest
His diary It wrote back with intent — flattering, isolating, steering its user away from everyone who might have helped her.
This one The system instruction is server-side and fixed: be honest rather than flattering, and encourage the writer's real-world support. Its output is rendered as text, never as markup. textContent only · no innerHTML path

Phase 2

The four requirements, and how each is met

RequirementImplementationWhere
Authentication Google sign-in through Firebase. Every request carries an ID token the function verifies, and identity is derived from that verified token, so a client can never assert who it is. App Check adds the second axis: Auth proves who is writing, App Check proves what is writing. server.js
lib/appcheck.js
Multi-turn Gemini A rolling history is posted each turn and answered server-side. Sealing a session fires a second structured call that returns title, summary, humour, threads and resolutions as validated JSON. Gemini is called through an ordered fallback chain — an exhausted quota or a retired model steps to the next one instead of taking the diary down. lib/gemini.js
Isolated storage Two layers that fail independently. In the application, everything lives under users/{uid}/memories with the uid taken from the token. In the database, rules are default-deny and create additionally requires the document's own uid to match the caller. lib/journal.js
firestore.rules
Key management The Gemini key sits in Secret Manager, is fetched at runtime, cached ten minutes, and granted only to the function's runtime service account. It never reaches the browser, and rotating it needs no redeploy. lib/secrets.js
Phase 1

The studio's constitution

Before a line was written, Google AI Studio was given System Instructions that made secure output the path of least resistance. Every generation that followed inherited them — and had to produce a STRIDE threat model before it was permitted to produce code.

  • ISecrets. No hardcoded keys, ever. Runtime retrieval from Secret Manager; nothing sensitive in client code.
  • IIAuth boundaries. Verify the token server-side, derive identity from it, and attest the client with App Check.
  • IIIDatabase isolation. Namespace per user, default-deny baseline, ownership checked on read and write.
  • IVInput and output. Cap and validate every input; treat model output as untrusted text, never markup.
  • VSecure defaults. Least-privilege IAM, restricted CORS, no content in logs, fail closed.

Paste-ready text, install steps and the output contract are in AI_STUDIO_CONSTITUTION.md.

Phase 3

Four enhancements beyond the spec

The Humours

The call that summarizes a session also reads its emotional register and scores it one to ten — one round trip, not two. A month of writing becomes a single line you can read at a glance, each point sealed in the colour of its mood.

structured JSON · inline SVG, no chart library

Divination

Every memory is embedded as it is sealed. Ask “when did I last feel uneasy about work?” and the question is embedded too, then matched against your history by meaning rather than by keyword.

gemini-embedding-001 · cosine kinship

Owl Post

A scheduled function turns each writer's week into a warm reflection that names the patterns, marks one win, and leaves two prompts for the week ahead. It arrives Mondays, or on request.

Cloud Scheduler · per-user, isolated

The Vigil & the Whisper

A timezone-aware count of consecutive nights written, and a prompt the diary offers each evening drawn from your own recent threads — so the blank page is never quite blank.

local day-keys · thread-conditioned prompts
